# Инструкции для агентов

## Общение

- Отвечай по-русски, если пользователь не попросил другой язык.
- Отвечай предельно кратко, сохраняя результат, выполненные проверки, риски и блокеры; подробности добавляй по запросу или когда без них ответ нельзя проверить.
- Пиши комментарии в коде по-русски.

## Проект

- Это MCP-сервер для Jira Server/Data Center 9.12.23. При изменении интеграции сверяй ресурсы, параметры и форматы с [официальным Jira REST API 9.12.23](https://docs.atlassian.com/software/jira/docs/api/REST/9.12.23/#api).
- Используй Jira REST API v2 (`/rest/api/2`). Не переноси решения из Jira Cloud API v3 без прямого запроса пользователя.
- Пиши на TypeScript в строгом режиме для Node.js 24.16.0+ и ESM. В относительных импортах исходников указывай расширение `.js`, чтобы скомпилированный код запускался в Node.js.
- Новые MCP-инструменты размещай в `src/tools`, наследуй от `MCPTool` и экспортируй по умолчанию. Задавай понятные `name`, `description` и Zod-схемы; валидируй через Zod входные данные и ответы Jira до возврата результата.
- Для HTTP-запросов к Jira используй `jiraClient` из `src/jira/client.ts`: endpoint, query-параметры и Zod-схему ответа определяет вызывающий tool. Прямой `fetch`, `getJiraUrl()` и `getToken()` используй только внутри клиента.
- Коды контролируемых Jira-ошибок бери из `JIRA_ERROR_CODE`; передавай клиенту контекстный код `404`, когда он зависит от операции.
- Сохраняй секреты вне репозитория: URL задаётся переменной `JIRA_URL`, токен читается из системного хранилища ключей сервиса `mcp-jira` с учётной записью `keyring:jira-token@mcp-jira`.

## Проверка изменений

- После добавления или изменения MCP-инструмента выполни `npm run build`, чтобы следующие сеансы MCP-потребителей загружали актуальную версию инструмента.
- После изменений запускай `npm run lint`, `npm run fmt:check`, `npm run types`, `npm test` и `npm run build`. Работа завершена, когда линтинг, проверка форматирования, проверка типов, тесты, TypeScript-компиляция и `mcp-build` проходят успешно.
