## Destination

Подготовить готовую к реализации спецификацию первого записывающего MCP-инструмента: безопасного выполнения разрешённого workflow transition Jira Server/Data Center 9.12.23 по ключу задачи и целевому статусу.

## Notes

- Домен: Jira issue workflow transitions; использовать Jira REST API v2 и официальную документацию Jira 9.12.23.
- В обсуждении пользователя «смена статуса» означает выполнение одного доступного workflow transition, а не прямую запись поля `status`.
- Вход: ключ задачи и целевой статус; статус сопоставляется без учёта регистра после обрезки пробелов.
- Несколько подходящих переходов дают ошибку. Недоступный статус даёт контролируемую ошибку со списком доступных целевых статусов.
- Если задача уже в целевом статусе, вернуть успех с `changed: false`.
- Инструмент меняет только статус; многошаговые маршруты и дополнительные поля перехода не поддерживаются.
- После записи обязательна проверка фактического статуса.
- Подтверждение мутации остаётся на стороне потребителя MCP.
- Результат: ключ задачи, прежний и новый статусы, выполненный переход и `changed`.
- При работе с картой применять `domain-modeling`; для HITL-решений также применять `grilling`.

## Decisions so far

- [Контракт Jira REST API 9.12.23 для workflow transition](issues/01-jira-transition-api-contract.md): зафиксирована последовательность чтения задачи и переходов, POST с ответом 204 и обязательная проверка; переходы с `required: true` нужно отклонять до записи.
- [MCP-метаданные записывающего инструмента](issues/02-mcp-mutation-metadata.md): `mcp-framework` 0.2.22 публикует стандартные annotations; инструмент следует объявить изменяющим состояние, destructive, идемпотентным и работающим с внешней системой.
- [Граница write API Jira-клиента](issues/03-jira-client-write-boundary.md): добавить узкий `postJsonNoContent`, строго принимающий 204, а метод, JSON-сериализацию, заголовки и транспортные гарантии обобщить только внутри клиента.
- [Публичный контракт и ошибки](issues/04-public-tool-contract-and-errors.md): выбран `change-issue-status` со стабильным результатом и тремя нормализованными ошибками выбора перехода; HTTP-статусы, URL и сырые ответы Jira потребителю не раскрываются.
- [Проверенная семантика записи](issues/05-verified-write-semantics.md): успех требует `204` и единственного GET с целевым status id; ошибки проверки различают неизвестный и наблюдаемо иной результат, а любые повторы оставлены потребителю.
- [Форма implementation handoff](issues/06-implementation-handoff-shape.md): проверенный черновик полностью задаёт реализацию и тестовые сценарии; общая политика сокрытия транспорта Jira закреплена отдельным ADR.

## Out of scope
