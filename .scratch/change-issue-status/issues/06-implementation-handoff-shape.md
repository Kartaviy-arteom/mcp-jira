## Question

Достаточно ли конкретен черновик implementation handoff — последовательность Jira-запросов, публичные Zod-схемы, изменения клиента, таблица ошибок и проверяемые сценарии — чтобы реализовать инструмент без новых продуктовых или архитектурных решений, и требует ли принятое решение отдельного ADR?

## Answer

Черновик [implementation handoff](../prototypes/implementation-handoff.md) проверен пользователем и признан достаточным для реализации без новых продуктовых или архитектурных решений. Он фиксирует затрагиваемые файлы, публичные и Jira Zod-схемы, последовательность запросов, узкий `postJsonNoContent`, таблицу нормализованных ошибок, правила гонок и исчерпывающий набор проверяемых сценариев.

Наблюдаемая семантика дополнительно проверена через одноразовый [интерактивный прототип](../prototypes/write-semantics.html): он различает no-op, подтверждённый переход, ошибку POST, неизвестный результат проверки и наблюдаемый конкурентный статус.

Отдельный ADR нужен только для общей политики публичных ошибок Jira. Потребитель получает `{ code, message, details? }` с кодом из контролируемого перечисления и не видит HTTP-статус, URL, сырой ответ, внутреннюю причину или сам транспорт общения с Jira. Решение принято в [ADR «Скрывать транспорт Jira за нормализованными ошибками»](../../../docs/adr/0001-normalize-public-jira-errors.md). Для workflow transition и узкого клиентского POST отдельный ADR не нужен: эти решения локальны и обратимы.

Неразрешённых продуктовых или архитектурных вопросов перед подготовкой итоговой спецификации не осталось.
