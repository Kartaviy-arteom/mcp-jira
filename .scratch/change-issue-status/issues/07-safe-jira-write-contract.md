# 07: Подготовить безопасный write-контракт Jira-клиента

**What to build:** подготовить проверяемую основу первого записывающего инструмента: MCP-потребитель получает только нормализованные ошибки без сведений о транспорте Jira, а Jira-клиент умеет безопасно отправить JSON POST с ожидаемым пустым успешным ответом.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Публичный payload каждой контролируемой Jira-ошибки имеет форму `{ code, message, details? }`, где код принадлежит действующему перечислению, а `details` присутствует только для явно нормализованных данных.
- [ ] Числовой HTTP-статус, URL, сырой ответ Jira, stack и внутренняя причина не сериализуются в MCP-ответ ни для существующих, ни для новых ошибок.
- [ ] HTTP-статус и причина могут сохраняться внутри ошибки для серверной диагностики без изменения публичного payload.
- [ ] Существующие безопасные сообщения и отображение Jira-ошибок в нормализованные коды сохраняются; меняется только раскрытие транспортных данных и возможность добавить нормализованные `details`.
- [ ] Публичный интерфейс Jira-клиента получает узкий `postJsonNoContent`, принимающий безопасный относительный pathname, необязательные query-параметры, JSON-совместимое body и необязательный контекстный not-found code.
- [ ] POST использует существующие гарантии безопасного URL, Bearer-аутентификации, timeout и запрета redirect, а также отправляет JSON content/accept headers.
- [ ] JSON сериализуется внутри клиента ровно один раз; ошибка сериализации становится `BAD_REQUEST` и не раскрывает body.
- [ ] Только `204 No Content` считается успехом; любой другой `2xx` становится `RESPONSE_FORMAT_ERROR`.
- [ ] Ошибочные ответы POST используют существующую классификацию Jira, включая переданный контекстный `ISSUE_NOT_FOUND`.
- [ ] Существующие GET, binary и probe интерфейсы сохраняют поведение, кроме согласованного удаления HTTP-статуса из публичных ошибок.
- [ ] Тесты через публичный MCP seam подтверждают новый внешний формат существующих ошибок и отсутствие приватных данных.
- [ ] Тесты через публичный seam Jira-клиента подтверждают метод, URL, headers, body, сериализацию, `204`, несовместимые `2xx`, HTTP-классификацию, timeout и отсутствие транспортных утечек.
- [ ] Линтинг, проверка форматирования, строгая проверка типов, все тесты, TypeScript-компиляция и MCP build проходят успешно.
