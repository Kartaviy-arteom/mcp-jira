# 01: Расширить получение Jira-задачи

**What to build:** Пользователь получает через `get-jira-issue` стабильное структурированное представление задачи с базовыми полями, иерархией, связями, версиями и временем изменения. Ключ задачи нормализуется и отклоняется до запроса, если не соответствует формату Jira.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Входной объект строгий, неизвестные поля отклоняются, `issueKey` обрезается, переводится в верхний регистр и проверяется до HTTP-запроса.
- [ ] Ответ сохраняет `id`, `key`, `summary`, `description`, `status` и добавляет `issueType`, `parent`, `subtasks`, `issueLinks`, `fixVersions`, `updated`.
- [ ] Отсутствующее описание возвращается как явный `null`, отсутствующий родитель — как `null`, отсутствующие связанные коллекции — как пустые массивы.
- [ ] Родитель, подзадачи и связанные задачи не раскрывают внутренние Jira ID; направление связи имеет только значения `inward` или `outward`.
- [ ] Версии содержат только ID, название и явные признаки `released` и `archived`.
- [ ] Ответ Jira проверяется схемой; несовместимый ответ преобразуется в безопасный `RESPONSE_FORMAT_ERROR`.
- [ ] Публичная выходная схема подключена к MCP Framework и результат доступен в `structuredContent`.
- [ ] Поведение покрыто тестами через публичный MCP-интерфейс, включая обе стороны связи, nullable description, пустые коллекции и ошибочный ответ.
- [ ] Линтинг, форматирование, типы, тесты и сборка проходят.
