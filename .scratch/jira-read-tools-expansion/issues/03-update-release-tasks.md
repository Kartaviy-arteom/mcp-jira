# 03: Обновить получение задач релиза

**What to build:** Пользователь получает страницу задач релиза по строгому числовому `releaseId`, видит статусы и данные пагинации, а описания запрашивает только при необходимости.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Строгий вход принимает `releaseId`, `includeDescription`, `limit`, `startAt`; старое поле `issueKey`, неизвестные поля и raw JQL отклоняются.
- [ ] `releaseId` содержит только цифры, `startAt` является целым неотрицательным числом с default 0, `limit` — целым числом от 1 до 100 с default 100.
- [ ] Jira получает фиксированный JQL только для `fixVersion`, а `startAt` и `maxResults` передаются отдельными query-параметрами без добавленной сортировки.
- [ ] Ответ содержит `tasks`, `total`, `nextStartAt`; каждая задача содержит ID, ключ, название и статус.
- [ ] `description` отсутствует по умолчанию и появляется как `string | null` только при `includeDescription: true`.
- [ ] `nextStartAt` рассчитывается по фактически полученному количеству задач и равен `null` на последней или пустой странице.
- [ ] Пустая страница при заявленном продолжении отклоняется как `RESPONSE_FORMAT_ERROR`.
- [ ] Вход и ответ Jira проверяются Zod-схемами, а выходная схема подключена к MCP Framework.
- [ ] Новый контракт и граничные случаи пагинации покрыты тестами через публичный MCP-интерфейс.
- [ ] Линтинг, форматирование, типы, тесты и сборка проходят.
