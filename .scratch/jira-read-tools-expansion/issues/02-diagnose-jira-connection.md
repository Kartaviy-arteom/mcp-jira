# 02: Добавить диагностику подключения

**What to build:** Оператор запускает `diagnose-jira-connection` без аргументов и получает безопасную независимую оценку конфигурации URL, наличия credentials, доступности Jira и состояния авторизации.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Инструмент имеет строгий пустой вход и возвращает только `configured`, `credentialsFound`, `reachable`, `authenticationStatus`.
- [ ] URL и наличие непустого токена проверяются локально и независимо.
- [ ] При корректном URL выполняется не более одного запроса `GET /rest/api/2/myself`, в том числе без токена; без токена заголовок `Authorization` отсутствует.
- [ ] Любой HTTP-ответ означает `reachable: true`; network, DNS, TLS, connection и локальный timeout означают `reachable: false`.
- [ ] С токеном `2xx` даёт `authenticated`, `401/403` — `rejected`, остальные HTTP-статусы — `unverified`; без токена статус всегда `unverified`.
- [ ] Некорректный URL предотвращает HTTP-запрос и даёт `configured: false`, `reachable: false`, `authenticationStatus: unverified`.
- [ ] Минимальное расширение Jira-клиента поддерживает диагностический запрос без credentials, не меняя его архитектуру и поведение обычных авторизованных запросов.
- [ ] Профиль, токен, URL, заголовки, тело Jira и исходные исключения не появляются в результате.
- [ ] Публичная выходная схема подключена к MCP Framework; все согласованные ветви покрыты тестами через MCP-интерфейс и существующий интерфейс клиента.
- [ ] Линтинг, форматирование, типы, тесты и сборка проходят.
